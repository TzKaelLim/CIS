**先講結論**：想改顏色、文字或手冊內容，不用自己寫程式。打開 Claude Code（在電腦上讓 Claude 幫你改檔案的工具），用平常說話的方式說要改什麼；看過預覽、確認之後，Claude 才會把修改送出。送出的修改要由核可人看過，再由有權限的人合併，合併後正式網站才會更新。

## 誰做什麼

| 角色        | 做什麼                                                       | 核可什麼                 |
| ----------- | ------------------------------------------------------------ | ------------------------ |
| 美編        | 決定 token（設計數值）的名稱和值、命名規範，以及手冊的設計說明 | token 的修改             |
| 工程        | 負責建置、自動檢查（系統自動確認修改沒有弄壞東西）和工具     | 建置、自動檢查和工具的修改 |
| 廠商        | 用同一套流程參與修改，能改哪些部分由雙方另外約定；修改一樣要由核可人看過才會合併 | —                        |
| Claude Code | 修改檔案、在你的電腦上跑檢查和預覽、整理成修改申請           | 不核可，也**不合併**     |

- 每一個修改都要送出「修改申請」（工程師叫它 MR），由核可人看過，再由有合併權限的人合併。誰有合併權限，由專案的管理者在公司的程式碼管理網站（GitLab）上設定。
- 自動檢查沒通過的修改申請不能合併。

## 你可以這樣跟 Claude 說

不用記指令，像跟同事說話一樣就可以。說得越具體，Claude 越不用猜。

      <li>「新增一個『成功』用的語意色，淺色和深色各給我兩個選擇。」</li>

      <li>「自動檢查在修改申請上失敗了，看一下是哪一步。」</li>
      <li>「幫我確認這次改動會影響哪些元件。」</li>

## Claude 會做什麼、不會做什麼

<div class="tc-dos not-content">
  <section class="do">
    <h3>會做</h3>
    <ul>
      <li>照你說的修改檔案，必要時一起更新用到它的地方。</li>
      <li>在你的電腦上跑自動檢查，並打開手冊預覽給你看。</li>
      <li>你確認後，整理成修改申請；送出前一定先問你。</li>
    </ul>
  </section>
  <section class="dont">
    <h3>不會做</h3>
    <ul>
      <li>不核可任何修改。</li>
      <li>不合併：合併一律由有權限的人來做。</li>
      <li>不部署：不會直接改動正式網站，正式網站只在合併後自動更新。</li>
    </ul>
  </section>
</div>

## 「核可」是什麼意思

**核可**＝負責那一塊的人看過修改申請，確認內容沒問題，同意它可以合併。

- token 的修改由美編核可；建置、自動檢查和工具的修改由工程核可。
- 核可不等於合併。核可之後，還要由有合併權限的人按下合併，正式網站才會更新。
- 核可人看的是修改申請上的說明和預覽頁面，不需要看懂程式碼。

## 第一次使用

<Aside title="電腦準備">
  第一次可以直接請 Claude Code 協助安裝。你需要：一個能登入公司程式碼管理網站（GitLab）、並能存取 UIKit 專案的帳號，以及裝好 Claude Code 的電腦。其餘需要的工具，Claude 會帶你一步步裝好。
</Aside>
