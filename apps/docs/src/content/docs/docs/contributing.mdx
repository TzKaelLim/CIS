**先講結論**：想改顏色、文字或手冊內容，不用自己寫程式。在 UIKit 的資料夾打開 Claude Code（在電腦上讓 Claude 幫你改檔案的工具），用平常說話的方式說要改什麼；看過預覽、你明確說可以之後，Claude 才會存下修改並送出「修改申請」（PR）。修改申請要由負責的角色核可，再由有合併權限的人合併。合併之後，目前不會自動更新任何網站：手冊和網站要部署到哪裡還沒有決定。

這一頁是摘要，寫給想知道「改一個東西要經過哪些人」的讀者。必須遵守的完整規則在 repository 的 `docs/rules/` 資料夾（一次修改怎麼做：`docs/rules/01-co-editing-sop.md`；網站之間的差異和用詞：`docs/rules/02-design-rules.md`），電腦準備和本機預覽在 repository 的 `CONTRIBUTING.md`。這一頁和它們不一致時，以 `docs/rules/` 為準。

## 誰核可什麼

| 角色         | 核可什麼（已決定）                         | 核可什麼（暫定，待決定）                                     |
| ------------ | ------------------------------------------ | ------------------------------------------------------------ |
| 美編（設計） | token 的名稱和值、命名規則、手冊的設計內容 | 元件的視覺設計和外觀                                         |
| 工程         | 建置、自動檢查（CI）、工具                 | 元件程式碼、相依套件、HeroUI 原始檔（`heroui/`）的修改       |
| 致遠（廠商） | —                                          | 用同一套流程參與修改；要不要核可、核可什麼，由專案負責人另訂 |
| 專案負責人   | —                                          | 共編規則和整體規格的修改、路線圖的批次調整                   |
| Claude Code  | 不核可，也**不合併**                       | —                                                            |

- 「已決定」那一欄是專案負責人的決定。「暫定」那一欄是決定之前的做法：Claude 照它在修改申請寫出需要誰核可，但它還要專案負責人確認，不是最後的分工。
- 每一個修改都經過修改申請（PR），由負責的角色核可，再由有合併權限的人合併。一個修改申請同時改到兩類內容時（例如 token 的值和建置的設定），兩個角色都要核可。
- 今天核可只是大家的約定，系統還沒有強制；自動檢查（CI）也還沒有建立，Claude 在你電腦上跑的檢查就是合併前唯一的關卡。
- 文件、修改申請和 repository 裡的任何檔案，人員只寫職稱，不寫姓名。唯一的例外在手冊裡：手冊用致遠這家廠商的公司名稱稱呼它，這是專案負責人的決定；手冊以外的檔案仍然寫「廠商」。

## 網站之間的差異分三級

一個網站想和其他網站不一樣時，依序判斷，用最低的那一級解決。動手前，Claude 會照這個順序問你，並把答案和理由寫進修改申請。

| 級     | 情況                                                   | 怎麼做                                                                         |
| ------ | ------------------------------------------------------ | ------------------------------------------------------------------------------ |
| 第一級 | 只有外觀的數值不同：顏色、圓角、陰影、邊框、字級、間距 | 這個網站的網站主題                                                             |
| 第二級 | 內容一樣，結構或排列不同（例如圖片在上面還是在左邊）   | 共用元件的一個變體，再由這個網站設定它的預設變體                               |
| 第三級 | 資料或功能不同，也就是別的網站沒有的東西               | 新元件：通用的放進 UIKit；只屬於一個網站的，留在那個網站自己的專案             |
| 不適用 | 所有網站一起改、文件、建置與工具                       | 照一般的規則修改預設值                                                         |

- 不可以為某個網站複製一份元件（例如「環保網的按鈕」）。
- 某個網站不用某個元件時，什麼都不用做。
- 網站主題的正式檔案和網站設定檔（各網站的預設變體）還沒有實作。需要它們時，Claude 會先停下來問工程，不自己發明做法。

## 核可人會看到什麼

**核可**＝負責那一塊的角色看過修改申請，同意它可以合併。核可不等於合併：核可之後，還要由有合併權限的人合併。

每一份修改申請的說明都用白話寫這五段：

1. **改了什麼**
2. **哪些畫面會變**
3. **請看哪幾頁**：頁面路徑，以及要選的網站主題和色彩模式（淺色／深色）。
4. **屬於哪一級**：第一級、第二級、第三級或不適用，以及理由。
5. **檢查結果**

核可人不需要看懂程式碼。要看預覽時，在自己電腦的 UIKit 資料夾打開 Claude Code，說「幫我開修改申請 #編號 的預覽」，Claude 會開好預覽並告訴你要看哪幾頁。
